# SquareFinder

A small convolutional neural network that looks at a hand-drawn shape and decides whether it's a square or not. You draw on a canvas with the mouse, press a key, and the model tells you what it thinks.

This project started as a fork of Null-byte-00/Imagerecognition, a 3-class shape classifier (house / smiling face / fish). SquareFinder rebuilds it as a binary classifier with a different architecture, a different dataset pipeline, and a more thorough training setup.

# The model

The network is a small CNN:

Feature extractor — two Conv2d → ReLU → MaxPool2d blocks, followed by a global max pool (AdaptiveMaxPool2d(1)).
Classifier head — Linear(8, 16) → ReLU → Linear(16, 1).

The input is a single-channel 64×64 array, where each pixel is 1.0 where there's ink and 0.0 for background (the opposite of the raw image, where white pixels are 255). The output is a single raw logit, not a probability. Applying sigmoid() to it converts it into a number between 0 and 1.

Label convention: 0 = square, 1 = not square. This matters because the raw sigmoid output is the probability of label 1, i.e. not square, not the probability of being a square. Anything that reads the model's output has to account for this (see main.py).

Why a global max pool, not an average pool or a flatten: a plain Flatten() straight into a Linear layer gives every spatial position its own independent weight, which means the network can learn to key off where the ink is on the canvas rather than its shape. Max pooling collapses each feature channel down to "did this feature fire anywhere in the image," which keeps the model's judgment independent of where on the canvas you draw.

# The dataset

The dataset is self-collected: roughly 140 hand-drawn PNGs, split into two folders:

square/ — squares, drawn at different sizes, positions, and with some natural wobble.
not_square/ — everything else: circles, triangles, rectangles, random polygons, scribbles, straight lines, and other non-square shapes.

Keeping the two folders roughly balanced in size matters. A model trained on a heavily lopsided split can reach high accuracy just by guessing the majority class every time, without learning anything about shape.

create_dataset.py converts every PNG in both folders into a single file, dataset.npz, containing:

X — shape (N, 1, 64, 64), float32, every image resized, grayscaled, and inverted (ink = 1, background = 0)
y — shape (N,), int64, the label (0 or 1) for each image

# Training

Loss: BCEWithLogitsLoss (binary cross-entropy applied to raw logits, with sigmoid handled internally for numerical stability)
Optimizer: SGD, learning rate 0.01, momentum 0.9
Split: ~85% train / 15% validation, held out and never trained on
Batching: mini-batches of 16, reshuffled every epoch
Epochs: trained for several hundred epochs; loss stays flat for a while before dropping sharply once the model finds a useful signal, so don't judge a run as "stuck" too early

train.py prints training and validation loss every epoch, then reports final accuracy — overall and broken down per class — on both the training set and the held-out validation set. Watching training and validation accuracy separately is what catches a model that's just memorizing its inputs rather than learning to recognize squares.

# File structure

draw.py	 - A pygame drawing canvas. Draw with the mouse; press s to save the current canvas as a PNG into a chosen folder and clear it for the next drawing.
create_dataset.py   - Reads every PNG in square/ and not_square/, converts each to a 64×64 array, and saves the combined dataset as dataset.npz.
model.py    - Defines the Model class: the network architecture, the training step, and save()/load() for the trained weights.
train.py    - Loads dataset.npz, trains the model with a train/validation split, prints per-epoch loss, and saves the trained weights to models.pt.
main.py     - Opens the drawing canvas, loads the trained model, runs inference on your most recent drawing, and prints the result.
dataset.npz     - The built dataset (generated by create_dataset.py)
square/, not_square/    - Raw training images, one folder per class.
cache/      - Folder where images get saved from main.py running
models.pt   - The trained model's saved weights (generated by train.py).

# Usage

1. Collect training data. Run the drawing tool once per class, changing the save folder between sessions:

bash
python draw.py

Draw a shape, press s to save it, repeat. Aim for a few dozen examples minimum per class, with real variety in size, position, and sloppiness.

2. Build the dataset:

bash
python create_dataset.py

This must be run from the project root, since it looks for square/ and not_square/ relative to the current directory.

3. Train the model:

bash
python train.py

Watch the printed loss. It should trend downward over time — if it's still flat near 0.69 (≈ ln(2)) after a long stretch, the model hasn't found a usable signal yet and something's likely off with the data or architecture rather than just needing more epochs.

4. Draw something and classify it:

bash
python main.py

A window opens. Draw a shape, press s to save it, then close the window. The model will classify your most recent drawing and print the probability it's a square.

Requirements
torch
numpy
pillow
pygame (or pygame-ce)

# Known limitations
The dataset is small and drawn entirely by two people, so the model may not generalize well to very different drawing styles, pen thicknesses, or image sources.

Training accuracy can reach 100% quite easily given the dataset size; a very tight fit is worth treating with some suspicion rather than as pure success, especially if real-world drawings that look clearly square or non-square to a human ever get misclassified.
